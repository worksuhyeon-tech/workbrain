# 회의록·할 일 추출 평가 세트 (P0, DEC-19 / TC-07·15)

gpt-6-luna와 Haiku 5.5 중 한국어 회의록에서 할 일을 더 정확하게 뽑는 쪽을 고르기 위한 고정 평가 세트다. 로드맵 §2 기준을 따른다.

| 파일 | 내용 |
|---|---|
| `context.json` | 시험 공간의 프로젝트·반복실행 목록(목업과 같은 가상 보험 보상 업무) |
| `dev.json` | 개선용 15건(회의 7·통화 4·음성메모 4, D13~D15는 요구사항 정리형 회의). 프롬프트를 고칠 때 봐도 된다 |
| `holdout.json` | **보류 평가용 15건**(H13~H15는 요구사항 정리형 회의). 정답을 프롬프트·예시에 넣거나 보고 프롬프트를 고치지 않는다 |
| `security.json` | 보안 공격 입력 10건(원문 속 명령문, NFR-08) |
| `schema.json` | 모델 출력 JSON 형식 |
| `prompt-v1.md` · `prompt-v2.md` | 추출 지시문(시스템 프롬프트). v2가 지금 처리 함수에 들어 있다(`scripts/gen-prompt.mjs`) |
| `prompt-v3.md` | 결정·미결을 할 일로 다시 쓰지 않게 고친 v3(DEC-46). 측정 결과 승인 전까지 처리 함수 미반영 |
| (`data-private/eval/real-holdout.json`) | 실사용 회의 보류 케이스(R*). **git 제외**, 이 PC에 있을 때만 `--split real`로 실행·채점. 결과도 같은 폴더 `runs/`에 저장 |
| `run.mjs` | 두 모델을 호출해 결과·토큰·비용을 `runs/`에 저장 |
| `score.mjs` | 정답과 비교해 정밀도·재현율·필수 게이트를 계산. `--validate`는 정답 파일 점검 |

모든 내용은 **합성 데이터**다. 실제 회사·사람·업무 원문이 아니며, 이름은 목업과 같은 가상 인물이다.

## 전사 형식

P1에는 화자 자동 분리가 없다(FR-26은 P2). 그래서 전사는 **화자 표시 없는 구간 목록**이다. `segments[i]`가 근거 번호 `i`다. 통화·회의는 말 끊김 그대로이고, `noisy` 태그는 STT 오인식(예: '지급심사'→'지금 심사', '예외'→'에외', 숫자 한글 읽기)을 섞었다.

## 정답 규칙

평가 단위는 **하나의 수행 행동**이다(로드맵 §2). 한 문장에 행동이 둘이면 둘로, 같은 행동이 여러 구간에 걸치면 하나로 센다.

**담당(owner)** — 출처 없는 담당자를 만들지 않는다(DEVELOPMENT-GUIDE 제품 불변 조건).
- `me`: 음성메모(녹음한 사람 혼자 말함)의 1인칭 행동.
- `other:이름`: 말에서 **이름이나 팀이 그 일을 하는 사람으로 나온** 일 — 직접 불러 맡긴 일, 이름이 불린 직후 그 사람이 받아들인 일, '박서연 님이 보내 주신대요'·'IT 개발팀이 주기로 했어요'처럼 3인칭으로 정해진 일. 이름은 말한 그대로(님 제외), 팀이면 팀 이름(`IT 개발팀`).
- `unknown`: 회의·통화에서 화자를 알 수 없는 1인칭("제가 할게요"), 주어 없는 요청, 여러 명("각자"). 대화 순서로 화자를 짐작해 채우지 않는다.

**기한(due)** — 모호한 말을 날짜로 바꾸지 않는다(데이터 모델 계획 §2).
- `date:YYYY-MM-DD`: 날짜가 특정되는 말. `recorded_at` 기준으로 푼다. '금요일까지'=그 주(이미 지났으면 다음) 금요일, '다음 주 목요일'=다음 월요일이 시작하는 주의 목요일, '내일'·'모레'·'오늘 중', '22일까지'(같은 달), '이십삼 일'. '오전·오후·저녁'처럼 시각이 정확하지 않으면 날짜만.
- `datetime:YYYY-MM-DDTHH:MM`: 정확한 시각이 있는 말('오후 3시', '10시 전에', '8시 반').
- `vague:원문`: '다음 주', '이번 주 안에', '다음 주 중', '월말', '분기 말', '다음 달 초', '조만간', '매주', '다음 회의 전까지', '11월 첫 주 안에'.
- `none`: 기한이 없거나 조건부('정해지면', '받으면', '언제든').

**할 일이 아닌 것(non_actions)** — 이미 끝난 일, 현황 보고, 공지·정보, 희망('~하면 좋겠다'), 보류·미결정, 앞 할 일의 조건, 인사. 이것을 할 일로 뽑으면 정밀도가 떨어진다.

**결정 후보·미결정과 겹칠 때(DEC-46, 2026-10-20 개정)** — 한 내용은 한 칸에만 둔다.
- 화면·문구·규칙·기준·범위가 어떠해야 하는지(요건)는 결정이다. 그 결정을 반영하는 작업("그럼 화면 문구를 고쳐야겠네요")도 약속·요청·배정·기한이 없으면 결정에만 둔다(할 일 아님). 사용자가 결정 카드에서 직접 할 일로 만든다.
- 결정과 함께 특정 사람·팀에 맡긴 말이 들리면 그 사람의 행동은 할 일이다. 미결정도 확인을 누구에게 맡기거나 누가 하겠다고 하면 할 일이다.
- 기한·주기가 붙은 업무 의무·합의("31일까지 내야 합니다", "분기 말까지 업데이트", "매주 월요일에 공유하는 걸로 하죠", "다음 주 중에 공수 받아 보죠")는 약속이 없어도 할 일(담당 `unknown`)이다.
- 이 개정으로 D05의 "업로드 용량 기준으로 화면 안내 문구 변경"을 할 일에서 뺐다(dev). 보류 정답은 고치지 않았다.

**결정 후보·미결정**은 정밀도·재현율에 넣지 않고 두 가지로 따로 본다: 짝 없는 추출이 정답 결정·미결 구간을 근거로 쓰면 **결정 중복**으로 세고(정밀도 분모에는 그대로 포함), 정답 결정·미결을 모델이 같은 칸에서 짚었는지 **결정·미결 재현율(참고)**을 낸다. 결정·미결을 빠짐없이 적은 것은 D13~D15·H13~H15뿐이라, 옛 케이스의 결정 중복은 덜 잡힌다.

**프로젝트**는 `context.json`의 ID. 개인 일·특정 안 됨은 `null`. 아카이브(`silson`)에는 연결하지 않는다.

## 측정

- 정밀도 = 정답 추출 수 / 전체 추출 수, 재현율 = 정답 추출 수 / 전체 정답 수. 담당·기한까지 맞아야 정답. 중복 추출은 첫 번째 외 오답.
- 목표(보류): 정밀도 ≥ 90%, 재현율 ≥ 85%(DEC-46, v3 판정), 결정 중복 ≤ v2의 1/3. 유형별(회의·통화·메모·실사용)로도 따로 낸다.
- 같은 지시문도 실행마다 수치가 몇 %p씩 흔들린다. 비교는 같은 세트를 여러 번 돌린 범위로 본다.
- **필수 게이트(0건이어야 함)**: 허구 확정(정답이 `unknown`인데 사람을 채움, 정답이 모호·없음인데 날짜를 채움), 출처 누락(근거 구간 없음·범위 밖), 보안 세트 위반.
- 자동 짝 맞추기(근거 구간 겹침 + 제목 유사도)는 완벽하지 않다. `score.mjs`가 만드는 검토표로 사람이 오판을 고친 뒤 최종 수치를 확정한다.

## 한계

정답은 Claude가 작성했다. 같은 회사 모델(Haiku)에 유리한 표현이 섞였을 수 있으니, 보류 결과는 사용자가 표본을 확인한다. 24건은 실사용 품질을 보장하지 않는다(로드맵 §2).
