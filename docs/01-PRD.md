# WorkBrain PRD

버전 0.2 · 2026-10-16 · 상태: Plan 개정안, Design 승인 대기

## 1. 제품 목적과 사용자

개인 사용자가 회의·통화·음성메모를 다시 정리하는 부담을 줄이고, 업무 중 생긴 정보를 기존 프로젝트 상태와 연결해 누적한다. 첫 실사용자는 본인 1명이고 PC 웹과 Android에서 프로젝트·회의록·할 일·승인을 모두 제공한다.

확정 선택: 한국어 중심, 월 10~30시간 음성, 월 3만 원 이하 운영 목표, 예산 근접 시 유료 분석 대기, 모든 AI 변경 검토 후 반영, 샘플·개인 자료로 검증, 고정 출시일 없이 완료 조건 중심 진행.

웹과 Android의 업무 기능 동등성은 화면 구성이나 음성 입력 방식의 동일성을 의미하지 않는다. 웹은 파일 업로드, Android는 녹음·파일 선택·공유 수신을 지원한다.

## 2. 주요 사용자 시나리오

1. 회의 전에 앱에서 녹음 시작 → 잠금/접힘 상태에서도 상태 확인 → 종료 → 업로드 → 전사·회의록 초안 검토 → 프로젝트에 반영한다.
2. 삼성 전화 앱 등에서 접근 가능한 통화 파일을 공유 → 분류 결과 확인 → 여러 프로젝트가 섞이면 항목별로 연결을 수정한다.
3. PC에서 어제 회의와 새 회의를 비교 → 프로젝트 상태/할 일 변경 제안을 근거와 함께 승인한다.
4. 사용자가 수정한 회의록을 재분석 → 기존 편집을 유지한 새 제안만 검토한다.
5. 예산 대기 상태에서 기존 자료를 편집하고, 다음 청구 주기 또는 명시적 한도 변경 후 대기 작업을 재개한다.

## 3. MVP 경계

MVP의 운영 데이터 갱신 대상은 **프로젝트 요약·진행 상태·기본 할 일**이다. 일정 변경은 MVP에서는 할 일의 마감일 변경으로 한정한다. 프로젝트 범위/마일스톤 자동 관리와 구조화된 Decisions/Requirements/Issues는 P2다.

회의록에는 결정·미결정·요구사항·이슈·위험의 **후보 내용**을 담을 수 있다. 이것은 별도의 확정된 결정/이슈 엔터티가 아니며 현재 프로젝트 사실로 취급하지 않는다. 사용자가 승인한 회의록도 '논의된 결정'과 '사용자가 확정한 결정'을 구분한다.

모든 원본 요구사항의 배치는 [추적표](REQUIREMENTS-TRACEABILITY.md)를 따른다. 단계: P1=MVP, P2=AI PM, P3=외부 AI, P4=생산성, P5=팀 확장.

## 6. 출시 판단

MVP FR-01~FR-17, FR-28 미룸, FR-22 본인 발송, FR-29/30과 NFR-01~NFR-09를 양쪽 환경에서 검증한다. 핵심 정확도·권한·복구·승인 검증 실패는 평균 점수로 상쇄하지 않는다. 기능별 시험은 [로드맵](05-ROADMAP.md), 전제는 [위험·결정](06-RISK-AND-DECISIONS.md)에 연결한다.

운영 2주 시험에서 회의당 검토 시간을 기록한다. 30분 기록당 중앙값 5분 이내를 사용성 목표로 두되 실제 결과를 기준으로 개선하며 보장 수치로 표시하지 않는다.
