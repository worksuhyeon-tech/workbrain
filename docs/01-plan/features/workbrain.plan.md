# WorkBrain PDCA Plan v0.2

> v0.2 개정 — Design 진입 전 Plan 보완

작성일: 2026-10-16 (Asia/Seoul) · 프로젝트 수준: Dynamic

**상태: Plan 개정안 작성. Design 미승인. 공급자·모델/비용 검증 G1/G2 미해소.**

## 목적

PC 웹과 Android에서 기록을 수집하고 기존 프로젝트와 비교해 변경을 제안하며, 사용자가 승인하면 근거와 함께 업무 지식이 축적되는 개인 AI 프로젝트 매니저를 만든다.

## 확정 범위

- 본인 1명, 한국어 중심, 샘플·개인 자료로 시작.
- 웹·Android 모두 프로젝트·회의록·할 일·검토·승인 제공.
- Android 회의/메모 녹음과 파일 선택·공유, PC 파일 업로드.
- 모든 AI 변경은 검토 후 반영. 월 10~30시간, 월 3만 원 이하 목표, 예산 근접 시 유료 처리 대기.
- 기한 없이 단계별 완료 조건으로 진행.
- MVP에서 갱신하는 운영 정보는 프로젝트 요약·상태·기본 할 일. 결정·요구·이슈는 회의록 후보로 남기고 구조화된 수명 관리는 P2.

## 주요 개정

1. 새 지침에 맞춰 bkend 우선 조건부 기준안으로 변경. Supabase/pgvector를 자동 채택하지 않음.
2. MVP 갱신 범위를 좁혀 비교 대상과 후속 구조화를 분리.
3. 10/20/30시간 사용량·재시도·재분석·BaaS 미확인 요금을 포함한 비용식 작성.
4. 보관 만료/원본만 삭제/연결 자료 삭제, 복구/백업 소멸 조건 구분.
5. 재분석과 수동 수정의 버전·중복·충돌 정책 추가.
6. 원문 지시를 데이터로 다루는 AI 신뢰 경계 추가.
7. 원본 요구사항의 모든 기능을 단계/제외 범위와 추적표에 배치.
8. 평가셋·정확도·녹음 손실·동기화 측정 조건 정의.

## 아키텍처 고려사항

Kotlin/Compose + Next.js/TypeScript + 공통 REST, 비동기 음성 작업, 비공개 파일 저장소를 기준으로 한다. bkend는 프로젝트 지침에 따른 우선 후보이나 가격·원자성·권한·복구를 아직 확인하지 못했다. G1/G2가 충족되지 않으면 실제 백엔드 종속 설계와 비용 확정을 중단하고 결정 기록을 갱신한다.

빈 저장소를 설치된 bkit의 로컬 detect-level 함수로 검사하면 Starter가 반환되었다. 파일 기반 자동 분류의 한계이며 제품 요구사항에 따라 Dynamic을 명시적으로 선택했다. MCP 연결을 새로 만들지 않았고, 설치된 로컬 pdca-plan 함수로 Plan 상태를 등록했다.

## 성공 기준과 단계 구분

이번 개정의 완료 기준은 6개 계획 문서·요약·추적표·검토 기록의 작성, 문서 간 정책 일치, 추적 ID/링크/비용 계산 확인이다. 이는 제품 구현 완료나 기술 검증 통과를 의미하지 않는다.

제품 MVP 완료 기준은 FR-01~FR-17, FR-28(검토 미루기 코어), FR-22(본인 주소 메일)·FR-29(Word)·FR-30(회의록 지침) 및 NFR-01~NFR-09의 해당 시험을 통과하고 양쪽 환경에서 수집→전사→검토→승인→동기화가 작동하는 것이다. FR-28의 리마인드 알림은 P4(FR-24) 연계로 MVP 필수에서 제외한다. 세부 시험과 실패 시 행동은 로드맵에 있다.

Plan 단계의 공식 승인/완료 전에는 G1/G2의 문서 근거 확인과 사용자 검토가 필요하다. Design 진입은 별도 승인 이후다. 공급자 실측은 Design 승인 후 P0에서 수행하며 조건이 깨지면 Plan을 다시 개정한다.

## 일정·협업·다음 행동

마감일을 임의로 정하지 않는다. G1/G2 근거 확인 → Plan 검토 → Design 승인 → P0 기술 검증 → P1a 기반 → P1b 수집 → P1c MVP → P2~P5 순서다.

공통 지침은 [DEVELOPMENT-GUIDE](../../DEVELOPMENT-GUIDE.md) 한 곳에 두고 AGENTS/CLAUDE는 진입점만 제공한다. 다음 작업은 [todo](../../../todo.md)의 Plan 검증 조건부터 수행한다.
