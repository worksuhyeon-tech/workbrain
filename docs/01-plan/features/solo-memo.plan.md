# 혼자 메모 처리 Plan — DEC-89 2단계

버전 0.1 · 2026-11-11 (Asia/Seoul) · 상태: **계획만(구현 금지, 사용자 결정 대기)**

근거: [DEC-89](../../06-RISK-AND-DECISIONS.md) · [Design §6.15](../../02-design/features/workbrain.design.md)

DEC-89 1단계로 빠른 입력 마이크를 길게 누르면 녹음 메모가 시작된다. 지금은 녹음이 끝나면 회의 녹음과 같은 길(올리기 → 받아쓰기 → 정리 → 기록 상세)로 간다. 이 문서는 혼자 메모를 **회의록 없이 할 일·아이디어 후보만** 남기는 2단계를 어떻게 만들지 정한다. 이 문서는 구현 완료가 아니다.

## 1. 목적과 성공 기준

- 목적: 걷다가·운전 전에 혼자 말해 둔 것을 회의처럼 다루지 않는다. 회의록 화면·참석자·결정 후보 없이, 해야 할 일과 떠오른 생각만 골라 검토하게 한다.
- 성공 기준(실사용 2주): 메모 1건당 할 일·아이디어 후보 중 사용자가 버리는 것 ≤ 1개, 지어낸 후보 0건, 1건 처리 비용 ≤ 10원.

## 2. 지금 있는 것(바꾸지 않아도 되는 것)

| 항목 | 지금 | 근거 |
|---|---|---|
| 기록 종류 | `source_record.record_kind`에 `memo`가 이미 있음. 올리기 창 '혼자 메모', 마이크 길게로 시작하면 처음 값이 '혼자 메모'(DEC-89) | `20261018001000_source_record_kind.sql`, `UploadSheet.kt` |
| 담당 | memo면 1인칭 행동을 '나'로(지시문 v5 담당 규칙, `extract.ts` `resolveOwner`) | `prompt.ts` prompt-v5 |
| 일정·마감 | memo에서는 정해진 일정·마감도 챙길 일로 뽑음(prompt-v5 원칙 3) | 같음 |
| 회의록 문서 | 자동으로 만들지 않고 기록 상세 [회의록 만들기]를 눌러야 만듦(DEC-79) | `process-record/document.ts` |
| 프로젝트 연결 제안·현재 상태 | 기록 단위 연결 제안(link-v2), 연결 뒤 현재 상태 제안(state-v1) | DEC-75·86 |

즉 할 일 후보는 지금도 메모에서 잘 나온다. 새로 필요한 것은 **아이디어 후보**와 **회의 전용 화면·칸을 메모에서 빼는 것**이다.

## 3. 바꿀 범위(안)

### 3-1. 처리 함수 `process-record`
- `record_kind = 'memo'`면 정리 지시문을 **memo-v1**로 바꾼다. 회의 지시문 prompt-v5는 그대로 둔다(회귀 위험 없음).
- memo-v1 출력: `actions`(지금과 같은 모양) + `ideas`(새 칸: 제목 1~60자, 한 줄 설명 0~300자, 근거 구간, 관련 프로젝트 ID 또는 null). `decisions`·`open_questions`·참석자 칸은 만들지 않는다.
- 아이디어의 기준: 사용자가 나중에 다시 볼 생각·제안·메모("이관 화면에 검색 칸 있으면 좋겠다"). 희망·감상은 할 일이 아니지만(prompt-v5 원칙 4) **아이디어로는 남긴다**. 이미 끝난 일, 인사, 혼잣말 추임새는 버린다.
- 지어내지 않는다: 모든 후보에 근거 구간, 말에 없는 날짜·사람·숫자는 넣지 않는다(NFR-02).

### 3-2. 서버(마이그레이션 1개, 반영 전 사용자 승인)
- `change_proposal.target_type`에 `'resource'`를 더한다(지금 `project_state·task·source_link`). DROP 없이 DO 블록으로 조건부로 제약을 바꾼다(서버 작업 규칙).
- `approve_proposal`을 넓혀 아이디어를 승인하면 `resource`(kind `note`, `title`·`note`, `source_record_id` = 그 메모)를 만들고, 프로젝트가 있으면 `resource_link`로 잇는다. 승인 이력은 지금과 같은 `approval_event`에 남긴다.
- DB 시험: `tests/p1/` 새 파일(끝 RAISE로 되돌림, DELETE 없음) — 아이디어 승인 → 자료 1개·연결 1개, 두 번 승인해도 1개, 다른 사용자 기록은 거부.

### 3-3. 앱
- 기록 상세: memo면 '회의록' 탭·[회의록 만들기]를 숨기고, '할 일 후보'와 '아이디어 후보' 두 묶음만 보인다. 전사는 지금처럼 아래에.
- 검토함: '아이디어 후보' 묶음([자료로 남기기]·[버리기]·미루기). 남기면 그 프로젝트의 '관련 자료'에 메모로 보인다(프로젝트가 없으면 '정리 안 됨').
- 기록 탭 목록 줄: 종류가 메모면 아이콘·글자를 '메모'로 구분(지금은 모두 녹음 아이콘).

## 4. 비용

- 받아쓰기 + 정리: 짧은 메모(1~3분) 1건 약 3~8원 예상. 근거: 10/18 20초 합성 녹음 2건이 받아쓰기 + 정리 합계 7원(`docs/03-analysis/p0-verification.md`). 메모는 회의록 문서를 만들지 않으므로 회의보다 적다.
- 프로젝트 연결 제안·현재 상태 제안: 지금과 같음(연결할 때 약 1~3원).
- 평가(아래 5): 약 10~20원(미리 승인 받기).
- 월 3만 원 목표 안에서 하루 메모 5건이면 한 달 약 1,000원 안팎.

## 5. 평가 방법

- 세트: `eval/llm/memo.json` 가상 메모 10건(합성 이름·회사만, 실제 기록 금지). 할 일만 있는 것 3, 아이디어만 3, 섞인 것 3, 아무것도 없는 것(추임새·감상) 1. 일정·마감 말, 모호 기한, '#프로젝트처럼 들리는 말', 지시처럼 들리는 말(보안) 포함.
- 정답: 건마다 할 일·아이디어 목록과 근거 구간.
- 지표: 할 일 정밀도·재현율(prompt-v5 보류 세트 기준 이상), 아이디어 재현율 ≥ 80%, 지어낸 후보 0, 보안 위반 0. 2회 돌려 둘 다 통과.
- 실행: `eval/llm/run-memo.ts`(기존 `run-state.ts`·`run-plan-head.ts`와 같은 모양), 결과 `docs/03-analysis/memo-v1-eval.md`.
- 회귀: 회의 지시문은 바꾸지 않으므로 회의 보류 세트는 다시 돌리지 않는다.

## 6. 사용자가 정할 것(만들기 전에 묻기)

1. 아이디어를 둘 곳: (가) 자료 메모(`resource` kind `note`, 추천 — 표·화면이 이미 있음) / (나) 새 '아이디어' 칸.
2. 아이디어 승인 위치: (가) 기록 상세와 검토함 둘 다(할 일 후보와 같음, 추천) / (나) 검토함만.
3. 메모 기록 상세에서 회의록 탭을 (가) 숨긴다(추천) / (나) 두되 처음에 접는다.
4. 길게 눌러 시작한 메모를 정지 뒤 올리기 창 없이 바로 올릴지: (가) 지금처럼 창을 띄움(저장 허용·동의 확인 때문에, 추천) / (나) 지난번 고른 값으로 바로 올림.

## 7. 순서(승인 뒤)

1. 6번 결정 → Design 절 추가 → 2. memo-v1 지시문·schema + deno 시험 → 3. 평가(승인된 비용 안) → 4. 마이그레이션 반영 전 시험 → 사용자 승인 → 반영 → 반영 후 시험 → 5. process-record 배포(사용자 승인) → 6. 앱(기록 상세·검토함·목록 줄) → 7. 실기기 확인.
