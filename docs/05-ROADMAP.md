## 1. 진행 방식

이번 작업은 Plan 문서 개정까지다. 아래 P0~P5는 **미래 개발 단계**이며 지금 실행한 작업이 아니다. PDCA 단계(Plan/Design/Do/Check)와 제품 출시 단계(P1 등)를 구분한다.

Design 진입 전 G1/G2의 문서 근거·비용 전제를 확인하고 사용자 승인을 받는다. 유료/인프라 생성이 필요한 시험은 해당 승인 범위에서만 한다. P0의 실측은 설계 승인 이후 구현 전 기술 검증으로 수행한다.

## 2. 검증셋과 측정 정의

초기 고정 평가셋은 합성/사용자 허용 개인 기록 24건: 회의 8, 통화 8, 음성메모 8. 각 유형에는 깨끗한 음성/잡음/장시간/모호한 기한/복수 프로젝트/상충 내용이 고르게 포함되게 한다. 서로 겹치는 특성은 태그로 기록한다. 별도 보안 공격 입력 10건을 추가한다.

24건 중 12건은 개선용, 12건은 보류 평가용으로 분리하고 보류 정답을 프롬프트에 넣지 않는다. 명시적 액션 아이템은 총 100개 이상, 모호하거나 액션이 아닌 후보 40개 이상을 사람이 정답으로 표시한다. 부족하면 표본을 추가하고 단순히 24건 수만 맞추지 않는다.

- 평가 단위는 하나의 수행 행동이다. 담당자·대상·기한이 명시된 경우 정확히 일치해야 정답 처리한다. 복수 행동을 한 항목으로 합쳐 누락시키면 누락으로 센다.
- 정밀도=정답 추출 수/전체 추출 수, 재현율=정답 추출 수/전체 정답 수. 중복 추출은 최초 1개 외 오답 처리한다.
- 목표는 보류 평가셋에서 정밀도≥90%, 재현율≥80%. 유형별 결과도 병기하고 낮은 유형을 전체 평균에 숨기지 않는다.
- 불명확한 담당자/기한/실명을 확정값으로 채우는 사례 0건, 승인 없는 상태 변경 0건, 출처 누락 0건은 별도 필수 게이트다.
- 전사 품질은 한국어 문자 오류율(CER)과 이름·숫자·기한 오류를 기록한다. CER 하나로 출시를 결정하지 않고 downstream 추출 목표와 근거 정확성을 함께 통과해야 한다.
- 작은 평가셋의 수치는 실사용 전체의 보장이 아니다. P1 2주 시험에서 수정률·검토시간·반려 원인을 추가 기록한다.

## 4. Plan 문서 검증과 운영 진입

Plan 문서 검증: 상대 링크 존재, 요구사항 ID 중복/누락, FR/NFR→화면·데이터·시험 연결, 비용 계산 재현, 비밀정보/개인 수신 주소 혼입, Design 자동 진입 여부를 점검한다.

첫 외부 배포는 별도 승인 후 개인 시험용으로 진행한다. 실제 회사 자료·공개 가입·스토어 공개는 포함하지 않는다. 실패한 핵심 시험은 다음 단계로 넘기지 않고 해당 Plan/Design을 개정한다. 배포 후 오류율·처리 지연·비용 편차·복구 실패를 추적할 계획이며 이번 작업에서 모니터/자동화를 생성하지 않는다.
