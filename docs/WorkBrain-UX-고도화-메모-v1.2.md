# WorkBrain UX 및 고도화 기획 메모 v1.2

> v1.1 대비 변경: Pin Board와 검토함 통합, "하나 고르기" 단계 신설(집중 시작 = 지금 할 일 확정), 회의 할일 추출 과다 문제 추가, KPI 축소, 보관 정책의 근거 링크 문제 추가, 미결정 사항 목록 신설.

## 제품의 핵심 목표

WorkBrain은 다수의 프로젝트를 동시에 진행하는 사용자가 업무 맥락을 잃지 않고, 떠오르는 아이디어를 안전하게 보관하며, 실제 수행 이력과 업무 습관을 분석할 수 있도록 돕는 개인 업무 운영 시스템이다.

**핵심 원칙: 떠오르는 생각은 놓치지 않고, 지금 하는 일은 방해받지 않으며, 실행할 일은 사용자가 결정한다.**

**보조 원칙: 앱 자체가 방해원이 되지 않는다.** 앱이 자동으로 만든 항목(회의 할일 후보, AI 추천 등)은 사용자가 고르기 전까지 "오늘" 화면에 들어가지 않는다.

## 하루 흐름 (모든 기능의 기준)

| 단계 | 사용자 행동 | 담당 기능 |
|---|---|---|
| ① 담기 | 생각·요청·회의를 즉시 맡긴다 | Quick Capture, 녹음 → 보관함 |
| ② 고르기 | 지금 할 1개를 정한다 | 오늘 탭 "지금 하는 일" + 집중 시작 |
| ③ 몰두 | 그 1개만 본다 | 뽀모도로, 나머지 접기 |
| ④ 끼어들기·복귀 | 새 일은 담아두고, 바꿨다면 돌아온다 | 끼어들기 버튼, 업무 재개 카드 |
| ⑤ 마감·주간 | 한 일을 확인하고 다음을 정한다 | 완료 취소선, PARA 화면, 주간 리뷰 |

새 기능은 이 다섯 단계 중 어디를 돕는지 설명할 수 있어야 한다.

## 1. 보관함 (Pin Board + 검토함 통합)

- 현재의 검토함과 신규 Pin Board를 **하나의 보관함**으로 통합한다. 확인할 곳이 두 군데가 되지 않도록 한다.
- 항목 종류는 **아이디어 / 할일 후보**(회의·녹음에서 추출) 두 가지로 표시만 구분한다.
- 저장만으로 할 일이 생성되지 않는다. 검토 결과는 **실행 / 계속 보관 / 아카이브** 세 가지로 통일한다.
- 실행을 결정한 항목만 실제 프로젝트·할 일로 전환한다.
- 검토되지 않은 항목 수는 숫자로만 표시하고, 빨간 배지 등으로 과도하게 강조하지 않는다.
- 보관함 정리는 매일 강제하지 않는다(주간 리뷰에서 비우는 것을 기본으로 한다).

## 2. Quick Capture

- 주요 화면 어디서든 접근 가능한 플로팅 퀵 캡처를 제공한다.
- 최소 입력은 자유 텍스트 한 가지. 프로젝트 분류, 마감일, 우선순위 입력을 강제하지 않는다.
- 현재 화면 또는 집중 중인 프로젝트 맥락은 자동 연결할 수 있도록 고려한다(자동 연결은 "추정"으로 표시).
- 저장 후 이전 화면으로 복귀한다. 집중 타이머는 퀵 캡처 중에도 계속 동작한다.
- 저장 위치는 1번 보관함이다.

## 3. 오늘 탭: 하나 고르기 (신규)

- 오늘 탭 최상단에 **"지금 하는 일" 1개 슬롯**을 둔다. 크게 표시하고, 나머지는 접는다.
- 지금 하는 일 외에 **예비 최대 2개**까지 둘 수 있다(오늘 총 3개 상한).
- 고를 때 후보는 기한이 임박한 순으로 3~5개만 보여준다. 전체 목록은 펼쳐서 볼 수 있다.
- 고른 1개에는 선택적으로 **"처음 2분 동안 할 동작" 한 줄**을 적을 수 있다(미루기 대응. 필수 아님).
- **끼어들기 처리**: 새 일이 들어오면 [담아두기](기본값) / [지금 바꾸기] 두 버튼만 제시한다.
  - 지금 바꾸기 시 하던 일은 자동으로 "멈춤" 칸으로 이동하고, "여기까지" 한 줄 메모는 선택이다.
  - 끼어든 일을 끝내면 "멈췄던 ○○로 돌아갈까요?"를 띄운다.
- **완료 항목은 사라지지 않고 취소선 + 흐린 색으로 하단에 남긴다.** 상단에 "오늘 완료 N건"을 표시해 "오늘 뭐 했지?" 하는 자책을 줄인다.
- 못 끝낸 일은 퇴근 시 버튼 하나로 내일 후보로 넘긴다. 실패로 표시하지 않는다.
- 알림은 오늘 마감인 일만 울린다.

## 4. 뽀모도로 연계

- 업무 재개 카드 또는 오늘 탭에서 "이 업무에 집중하기"를 누르면 집중 세션을 시작하고, **그 일이 자동으로 "지금 하는 일"이 된다**(고르기와 집중 시작을 한 동작으로).
- 기본 25분, 길게 눌러 45분·60분으로 변경한다. 시작할 때마다 시간을 묻지 않는다.
- 타이머 종료 시 강제로 멈추지 않고 "계속 / 쉬기"를 고른다(몰입 흐름을 끊지 않기 위함).
- 세션을 업무 또는 프로젝트에 연결하고, 실제 집중 시간을 기록한다.
- 일시중지·종료 시 체크포인트(마지막 완료 내용, 다음 행동, 중단 이유)는 모두 선택 기록이다.
- 집중 시간과 업무 진척률을 혼동하지 않는다.

## 5. 업무 재개 카드

- 프로젝트 또는 업무를 다시 열면 마지막 진행 상태와 다음 행동을 표시한다.
- 사용자가 따로 적지 않아도 **마지막으로 연 항목·마지막 세션은 자동으로 기억**한다. 사용자 메모는 있으면 우선 표시한다.
- 확정된 할 일, 회의록, 사용자 체크포인트를 우선 활용한다.
- AI가 추론한 내용은 확인된 사실과 명확히 구분한다.
- 집중 시작 전 별도의 복잡한 입력을 강제하지 않는다.

## 6. PARA 프로젝트 화면

- **위치: 매일 쓰는 실행 화면이 아니라, 주간 점검과 맥락 확인용 화면이다.** 실행은 오늘 탭에서 한다.
- 기존 PARA 4대 분류와 다단계 트리구조를 유지한다. 트리의 위치는 안정적으로 유지한다.
- 트리 + 업무 지도맵 결합 디자인을 검토한다(예: 트리를 기본으로, 프로젝트 선택 시 연관관계를 지도처럼 표시).
- 폴더에는 여러 상태 뱃지를 표시하지 않고, 개입이 필요한 경우에만 작은 색상 점을 사용한다.
- 모든 지연 업무를 빨간 점으로 표시하지 않는다. 지연 사실은 상세 화면과 전체 지연 목록에서 확인한다.
- 연관 프로젝트는 해당 프로젝트를 선택했을 때 표시한다.
- 프로젝트 상세에는 다음 행동, 마지막 진행 상황, 최근 회의 및 연관 업무를 제공한다.

## 7. 회의 할일 추출 개선 (실사용 문제, 신규)

**현상(2026-10-19 실사용)**: 12분 회의에서 할일 후보 6개가 추출됨. 그중 3개는 "결정 후보"·"정하지 못한 것"과 내용이 중복됨. 실제 할일은 3~4개가 적정.

**원인 추정**:
- 지시문(prompt-v2)이 할일을 "앞으로 하기로 한 행동"으로 정의 → 기획 회의의 결정("표기를 ~로 바꾼다")도 할일로 이중 분류.
- 평가 세트(합성 24건)가 결정·미결을 점수에 넣지 않아 중복이 측정되지 않음.
- 모델이 재현율 우선(정밀도 87.5% / 재현율 98.2%)으로 맞춰져 있음.
- 화자 분리가 없어 모든 후보가 "담당 확인"이라 내 일/남의 일로 거를 수 없음.

**개선 방향**:
1. 지시문 v3: 결정·미결에 이미 쓴 내용을 할일로 다시 쓰지 않는다. 할일은 약속·요청이 들린 것("제가 할게요", "~해 주세요", "~하기로 해요")만 뽑고, 요구사항("~로 바꾼다", "~해야 한다")은 결정에 남긴다.
2. 결정 카드에 "할일로 만들기" 버튼을 둔다(덜 뽑아도 놓치지 않게).
3. 평가 세트에 "요구사항 정리형 회의"를 가상 데이터로 추가하고, 결정 중복을 오답으로 센다.
4. 추출된 후보는 1번 보관함으로만 간다. 오늘 탭에 자동으로 들어가지 않는다.

## 8. 녹음·회의록 화면 소소한 개선

- 녹음 업로드 시 참석자와 함께 **제목도 바로 수정**할 수 있게 한다.
- 회의록 처리 시 "처리 중 문제가 생겼어요: No refresh token found in current session" 문구가 뜨지만 결과는 정상 출력됨 → 원인 확인 후, 결과가 정상이면 사용자에게 오류 문구를 노출하지 않는다.
- 할일 보기에서 "고치기" 버튼을 없애고, **"담당 확인" 뱃지를 눌러 담당자 변경, 날짜를 눌러 기한 변경**하는 직접 편집 방식으로 바꾼다.

## 9. KPI 및 AI 주간 리뷰

**1단계(먼저 시작)**:
- 프로젝트별 집중 시간
- 할 일 완료 및 지연 현황
- 중단 사유(체크포인트에 기록된 것)

**2단계(뽀모도로 데이터가 충분히 쌓인 뒤)**:
- 마감 준수율, 업무 착수까지 걸린 시간, 업무 전환 빈도, 반복 중단 패턴, 프로젝트별 시간 배분, 업무량과 가용 시간 비교

원칙:
- AI 리뷰는 객관적 측정값과 추정 원인을 구분하고, 다음 주 우선순위(핵심 3개)를 추천하되 확정 권한은 사용자에게 남긴다.
- 업무 과부하, 외부 회신 대기, 요구사항 불명확성 등도 함께 분석하여 모든 지연을 개인의 집중력 문제로 판단하지 않는다.
- 주간 리뷰에서 보관함 비우기(실행·보관·아카이브)를 함께 진행한다.

## 10. 데이터 보관

- 원본 음성: 30일 유지(현행 유지).
- 전사 텍스트: 6개월 유지(현행 유지).
- **승인된 회의록: 무기한 보관으로 변경**(현행 1년, `settings.retention_knowledge_years` 기본 1).
- 기타 지식·아이디어·집중 세션의 보관 정책은 추후 정의.

**확인된 영향(사전 분석)**:
- `meeting_version.retention_expires_at`이 NOT NULL이라 무기한 보관에는 스키마 변경이 필요하다.
- 할일·회의록은 전사 구간을 근거로 연결된다(`evidence_link`). 전사가 6개월 후 삭제되면 **승인된 회의록의 근거가 끊긴다.** 다음 중 하나를 결정해야 한다:
  - (A) 승인 시 근거 문장을 회의록·할일에 함께 저장
  - (B) 승인된 기록의 전사는 회의록과 같은 기한으로 보관
- 사내 문서 보존 규정이 있으면 그 기준을 우선한다.

## 11. 미결정 사항 (임의로 확정하지 않음)

- PARA "개입 필요" 점의 기준(예: 오늘·내일 마감, 회신 대기 N일 초과)
- 보관 정책의 근거 링크 처리 방식(10번 A/B)
- 예비 할 일 상한(2개)과 고르기 후보 수(3~5개)의 적정값 — 1주 실사용 후 조정
- 화자 분리 도입 전, 회의 할일의 "내 일" 식별 방법
- 트리 + 지도맵 결합 디자인의 구체 형태

## 12. 개발 진행 원칙

- 현재 PRD와 P1~P4 로드맵을 먼저 확인한다.
- 새로운 아이디어를 이유로 기존 개발 우선순위를 임의로 변경하지 않는다. 단, 7번(실사용 문제)과 8번(소소한 개선)은 P1 실사용 품질 개선으로 분류할 수 있는지 검토해 제안한다.
- 이번 신규 기능은 우선 고도화 백로그에 기록한다.
- 향후 기능 연동에 필요한 데이터 관계와 확장 포인트를 검토한다.
- 기능이 추가되어도 사용자 입력·관리 부담이 증가하지 않도록 한다.
- 자동 수집 가능한 정보는 자동화하고, 중요한 실행 결정은 사용자가 한다.

**권장 검증 순서**: 3번(오늘 탭) → 3번의 끼어들기 처리 → 7번(추출 개선) → 4·5번 → 6·9번. 1~2단계를 1주 써보고 실제로 하나에 몰두되는지 확인한 뒤 다음으로 넘어간다.

## Claude Code에 요청할 작업

1. 현재 저장소의 PRD(`docs/01-PRD.md`), UX 문서(`docs/04-UX-PLAN.md`), 데이터 모델(`docs/03-DATA-MODEL-PLAN.md`), 로드맵(`docs/05-ROADMAP.md`), 결정 기록(`docs/06-RISK-AND-DECISIONS.md`)과 이 메모를 비교한다.
2. 기존 기능과 중복되는 내용, 수정해야 할 내용, 신규 고도화 아이디어를 구분해 표로 정리한다. 특히 검토함과 보관함 통합, FR-25(뽀모도로·통계, P4)와 이 메모의 관계를 명시한다.
3. 기존 로드맵을 유지한 채 기획 문서 및 백로그(`todo.md` 등)에 반영한다.
4. 승인된 회의록 무기한 보관 정책의 코드·DB 영향 범위를 분석한다(마이그레이션, purge 함수, 설정 화면, 근거 링크 처리 A/B 각각의 영향).
5. 7번 추출 개선에 대해 지시문 v3 초안과 평가 케이스 추가 계획을 제안한다(`eval/llm/`, DEC-28 절차 준수. 실제 회의 원문은 넣지 않고 가상 데이터로 만든다).
6. 이번 요청으로 신규 기능을 바로 구현하거나 개발 우선순위를 변경하지 않는다. 변경이 필요하다고 판단되면 제안만 하고 사용자 승인을 받는다.
