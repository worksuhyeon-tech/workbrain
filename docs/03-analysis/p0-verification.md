### 시험 중 발견해 고친 결함

1. **승인 표시가 트랜잭션 끝까지 남음** (0400): `approve_proposal`이 켠 'AI 제안 승인' 표시가 같은 트랜잭션의 이후 수동 편집까지 `ai-approved`로 기록할 수 있었다. 할 일을 쓰는 순간에만 켜고 바로 끄도록 바꿨다.
2. **트리거의 비단락 평가** (0500): PL/pgSQL은 `TG_TABLE_NAME = 'project' AND NEW.area_id ...`에서 앞 조건이 거짓이어도 뒤를 읽어, `area` 삽입이 실패했다. 테이블 확인과 열 접근을 중첩 IF로 나눴다.

### TC-08 실제 동시 요청 — REST 경로 (2026-10-18)

시험: `tests/p0/tc08_concurrent_seed.sql` + `tests/p0/tc08_concurrent_rest.mjs`. 같은 계정으로 두 세션(두 기기 역할)을 로그인해 공개 REST(`/rest/v1/rpc/approve_proposal`)로 동시에 요청했다. 임시 계정은 시험 뒤 삭제(잔존 0).

**결과: 9/9 통과**
- 같은 새 할 일 제안 20건을 두 세션이 동시에 승인(요청 40개를 한꺼번에, 584ms) → 20쌍 모두 `approved` 1 + `already-approved` 1, 할 일 20건(중복 0), 승인 기록 20건.
- 같은 기준 버전의 프로젝트 상태 변경 10건을 동시에 승인 → 1건 반영, 9건 `conflict`, 상태 버전 1개.
- 로그인 없이 공개 키만 → 테이블 읽기·승인 RPC 모두 HTTP 401.

### 보안 점검(Supabase advisor)

- `approve_proposal`·`reject_proposal`을 로그인 사용자가 실행할 수 있다는 경고 2건. **설계 의도대로**다(운영 데이터 변경의 유일한 길이며, 함수 안에서 `auth.uid()`와 소유자를 직접 확인한다. 위 '승인 건너뛰기'·'남의 제안 승인' 시험으로 확인).
- RLS 미적용 테이블 경고 없음.

### 아직 확인하지 않은 것 (TC-01/08 나머지)

- **공개 가입 차단**: Google 로그인(DEC-26)이라 대시보드의 '새 가입 허용'을 끄면 본인 첫 로그인도 막힌다. 대신 계정 생성 전 DB 훅에서 본인 Gmail 외에는 거부하고, 다른 주소로 가입 시도 → 거부를 확인한다(Google OAuth 연결 후).
- **저장 암호화(M10)**: Supabase 관리 저장소 암호화를 공식 문서로 확인해 기록한다.

## 2. TC-12 백업·복원 — DB 계층 통과, GCS 연결 전 (2026-10-18)

마이그레이션 0600(`wb_backup_export`·`wb_tombstone_export`·`wb_backup_restore`)·0700(부모 없는 행 정리). 시험: `tests/p0/tc12_backup_restore.sql`. **결과: 11/11 통과**

- 백업1 → 할 일 t2 영구 삭제(원장 기록) + t3 삭제 요청(7일 복구 대기) → 백업2·원장 내보내기.
- 백업2에 복구 대기 t3가 빠짐(제외 1건).
- **오래된 백업1을 복원해도 t2가 되살아나지 않음**(원장 1건 적용), **t2의 이력(제목 스냅샷)도 남지 않음**(부모 없는 행 1건 정리), 나머지 할 일·자료 연결은 복원, 운영 테이블은 그대로.
- 삭제 원장이 없거나 백업보다 오래되면 복원 거부. 로그인 사용자·anon은 내보내기·복원 함수 실행 불가(advisor 경고 없음).
- 시험 중 발견해 고친 결함: 원장으로 부모만 지우면 자식 행(지운 할 일의 `task_revision`)에 제목이 남아 되살아남 → 0700에서 외래 키를 따라 연쇄 정리.
- 암호화(`scripts/backup/crypto.mjs`): 왕복 일치, 암호문에 평문 없음, 틀린 암호·변조 파일·12자 미만 암호문 거부 확인.
- **남은 것**: GCS 버킷·서비스 계정 생성(사용자, DEC-29) 후 `.github/workflows/backup.yml`을 켜고 실제 업로드 → 내려받기 → `scripts/backup/restore.mjs` 복원까지 한 번 돌린다. 한계: 백업 시점 이후에 생긴 '복구 대기' 요청은 그 백업에 반영되지 않는다(복구 대기는 아직 영구 삭제 전이라 원장에 없음).

### 3-0-1. 2차 실행 (prompt-v2, 2026-10-18)

v2는 개선용 세트의 오류 유형만 규칙으로 옮겼다: 회의·통화에서 me 금지와 대화 순서 추측 금지 예시, 한 대상에 이어지는 단계는 하나로, 바뀐 기한·조건부 약속은 할 일, 메모의 일정·마감은 챙길 일, 녹음 당일 표현은 날짜, '이번 달 안에'는 모호. 보류 전사의 8글자 연속 구절이 v2에 새로 들어가지 않았음을 기계로 확인했다. **다만 1차 보류 결과의 오류 유형을 본 뒤 작성했으므로 보류는 더 이상 완전한 미공개 세트가 아니다.** 다음 측정은 P1 실사용 기록으로 한다.
