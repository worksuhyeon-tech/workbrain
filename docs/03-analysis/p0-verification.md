### 시험 중 발견해 고친 결함

1. **승인 표시가 트랜잭션 끝까지 남음** (0400): `approve_proposal`이 켠 'AI 제안 승인' 표시가 같은 트랜잭션의 이후 수동 편집까지 `ai-approved`로 기록할 수 있었다. 할 일을 쓰는 순간에만 켜고 바로 끄도록 바꿨다.
2. **트리거의 비단락 평가** (0500): PL/pgSQL은 `TG_TABLE_NAME = 'project' AND NEW.area_id ...`에서 앞 조건이 거짓이어도 뒤를 읽어, `area` 삽입이 실패했다. 테이블 확인과 열 접근을 중첩 IF로 나눴다.

### 보안 점검(Supabase advisor)

- `approve_proposal`·`reject_proposal`을 로그인 사용자가 실행할 수 있다는 경고 2건. **설계 의도대로**다(운영 데이터 변경의 유일한 길이며, 함수 안에서 `auth.uid()`와 소유자를 직접 확인한다. 위 '승인 건너뛰기'·'남의 제안 승인' 시험으로 확인).
- RLS 미적용 테이블 경고 없음.

### 아직 확인하지 않은 것 (TC-01/08 나머지)

- **실제 동시 요청**: 위 시험은 한 연결에서 순서대로 실행했다. 두 기기가 같은 순간 REST(`/rpc/approve_proposal`)로 승인하는 시험은 비밀번호 로그인 시험 계정과 공개 키가 필요해 다음 단계에서 한다.
- **공개 가입 차단**: Supabase 대시보드 Auth 설정에서 이메일 가입을 끄는 것은 사용자 작업이다(FR-01). 끈 뒤 가입 시도 거부를 확인한다.
- **저장 암호화(M10)**: Supabase 관리 저장소 암호화를 공식 문서로 확인해 기록한다.
