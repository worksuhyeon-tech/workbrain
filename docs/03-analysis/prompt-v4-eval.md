# 지시문 v4 평가 결과 (DEC-76 이름 붙은 화자 담당 · DEC-77 받는 사람)

2026-11-09~10 · gpt-6-luna · 절차 DEC-28(평가 → 생성 스크립트 → 배포)

## 1. 바꾼 것

- 할 일 정리 입력: 가져온 txt의 화자 이름을 줄마다 `[번호] (이름) 문장`으로 붙인다. 번호 화자('참석자 3')는 붙이지 않고, '(나)'·내 이름은 `(나)`.
- 담당 규칙: 이름이 붙은 줄의 1인칭 약속은 그 화자, 이름 없는 줄·'저희가'·주어 없는 요청은 확인 필요(DEC-27 유지), 요청한 사람은 담당이 아님.
- 받는 사람: `actions[].recipients`(결과를 받는 사람·팀, 최대 5명).
- 용어 교정: 화자가 있는 기록은 발언 한 줄씩 교정해 줄 수를 지킨다(교정본에도 화자가 남음).
- 원문은 저장소에 두지 않는다. 실제 회의 원문·결과는 `data-private/eval/`(git 제외)에만 있다.

## 2. 실제 회의 5건(화자 이름 있음)

| | 지금(v2, 화자 없음) | v4 |
|---|---|---|
| 할 일 후보 | 38 | 39 |
| 담당 '확인 필요' | 37 | 9 |
| 말한 사람 기준으로 채운 담당 | – | 29 |
| 받는 사람이 있는 할 일 | – | 18 |

근거 줄을 열어 확인: 분명히 틀린 담당 0건, 애매 2건("한번 체크를 해봐야죠" 같은 말을 담당으로 봄). 제목에 화자 표시 '(나)'가 들어간 1건 → 지시문에 금지 한 줄 추가(이 뒤로 실제 회의는 다시 돌리지 않음). 비용 31.6원.

## 3. 화자 방법 채점표(A 글자 맞추기 vs B 교정이 발언 줄을 지킴, 사용자 요청)

| 항목 | A | B |
|---|---|---|
| 교정본에서 화자가 붙은 줄 | 1,664/2,642 (63%) | 3,311/3,400 (97%, 나머지는 번호 화자) |
| 담당 '확인 필요' | 16/41 | 9/39 |
| 말한 사람 기준 담당 | 22 | 29 |
| 받는 사람 있음 | 10 | 18 |
| 용어 교정 반영(짧은 3건, 원문보다 늘어난 용어집 낱말) | 22 | 21 |
| 교정이 줄 수를 지킨 묶음 | – | 12/12 |

A가 놓친 원인: 기존 교정은 문장부호 없는 발언 여러 개를 한 문장으로 합쳐 한 문장에 두 사람 말이 섞였고, A는 그런 문장에 화자를 붙이지 않는다. B의 할 일 결과는 2절(교정 전 발언 줄 + 용어집)을 썼다(줄 모양이 같고 용어만 다름). 사용자가 B로 확정(2026-11-10). 비용 57원.
