# WorkBrain UX 계획

버전 0.2 · 2026-10-16 · 화면 설계 전 정보 구조와 행동 기준

## 1. 정보 구조

주 탐색: 오늘 / 프로젝트 / 기록 / 검토함 / 검색. 계정·연결·보관·비용·동의는 설정에 둔다. 녹음은 Android의 상시 접근 가능한 주요 행동으로 제공한다. 웹은 업로드 행동을 같은 위치 계층에 둔다.

PARA는 별도의 복잡한 네 앱으로 나누지 않는다. 프로젝트 화면 왼쪽의 **페이지 트리**에 사용자 PARA 폴더 이름 그대로 `1. 프로젝트 / 2. 반복실행 / 3. 관심영역 / 4. 아카이브`를 펼쳐 보여 준다. 자료는 여러 프로젝트·반복실행에 연결하고, 끝난 것은 4. 아카이브에서 복원한다. 트리 위에는 업무 공간 전환이 있다. 지금은 `본업(보상시스템 기획)` 하나이고, 부업 공간은 나중(P4)에 추가한다(DEC-22).

초안과 확정 데이터를 상태 라벨로 구분한다. AI 신뢰도 숫자는 사실성 보증처럼 강조하지 않으며 사용자가 이해할 수 있는 연결 이유와 근거를 우선 표시한다.

## 3. 플랫폼 전략

Android 접힌 화면은 한 패널에 기록·확인 행동을 우선한다. 펼친 화면은 목록/상세 두 패널, 충분한 폭에서 근거 패널을 추가한다. 고정 기종 해상도에 의존하지 않고 창 크기·힌지·회전·다중 창을 고려한다. 펼치면서 녹음이나 편집이 초기화되지 않아야 한다. [Compose 적응형 UI](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps)

PC는 탐색/목록/상세 패널을 제공하고 검토 시 전후 비교와 출처를 함께 보여준다. 키보드 이동과 명확한 포커스를 제공한다. 색만으로 승인/위험/실패를 표현하지 않는다.

| 행동 | Android | PC 웹 |
|---|---|---|
| 앱 내 녹음 | P1 | 제외 |
| 파일 업로드 | 선택·공유 수신 | 파일 선택·드래그 |
| 프로젝트/회의록/할 일/승인 | P1 | P1 |
| 오프라인 녹음·업로드 대기 | P1 | 해당 없음 |
| 오프라인 프로젝트 편집/승인 | 제외, 조회 캐시만 | 제외, 조회 캐시만 |
| 처리 상태·예산·보관 설정 | P1 | P1 |

## 4. 주요 여정과 실패 복귀

### 회의 수집

홈 → 녹음 시작(기존 권한 부여 시 홈에서 2번 이내 탭) → 로컬 저장 → 종료 → 업로드 동의/예상 비용 → 전사 → 비식별화 미리보기 및 분석 동의 → 회의록/제안 검토.

동의는 계정 설정에 저장 가능하지만 공급자·처리 목적이 바뀌면 다시 확인한다. 처음 사용 시 권한 시스템 대화상자는 탭 수 목표에서 분리해 측정한다.

잠금 후에도 시작된 녹음의 상태를 알 수 있게 알림을 제공한다. 강제 종료 후 자동 녹음 재개를 약속하지 않는다. 앱 재실행 시 보존 파일과 중단 시점을 보여준다. [Android 서비스 제한](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start?hl=en)

### 변경 승인

검토함 → 변경 대상/전후 값 → 근거 문장과 원본 상태 → 수정 또는 승인/거절. 일괄 선택은 명시적으로 수행하고, 상태 전환·기한 변경은 상세를 확인한 후 적용한다. 일부 실패 시 항목별 결과를 보여준다.

다른 기기에서 먼저 편집했으면 승인을 실행하지 않고 최신 상태와 제안을 다시 비교한다. 근거가 삭제되었으면 새 근거 확보 또는 제안 폐기를 안내한다.

### 재분석

전사/회의록 편집 → 변경 저장 → 재분석 예상 비용 확인 → 새 버전 생성 → 기존 승인/수동 편집과 차이 검토. 원본 복원·재생성은 별도 행동이다. 재분석 버튼이 승인된 회의록을 즉시 교체하지 않는다.

### 삭제

원본 상세/설정 → '원본만' 또는 '연결 자료까지' 선택 → 영향 목록·남는 자료·복구 기한 확인 → 삭제. 자동 보관 만료는 알림/설정에서 일괄 영향 확인. 외부 내보내기 사본은 회수되지 않음을 표시한다.

### 예산 대기

작업 상세에서 이유·예상 비용·다음 재개 조건을 표시한다. 가능한 행동은 취소/보관/다음 주기 대기/설정 변경이다. 무료로 바뀐 것처럼 재시도 버튼을 표시하지 않는다. 기본 조회·수동 편집은 유지한다.

## 5. 벤치마크와 디자인 원칙

TickTick의 빠른 입력, 오늘 보기, 목록 필터, 우선순위는 행동 패턴으로 참고한다. 빠른 입력은 P1에서 규칙으로 해석한다(AI 비용 0, DEC-23). 캘린더·매트릭스는 P4이며 모든 할 일에 보기 전환 자리만 먼저 둔다. 습관/집중은 P4로 배치한다. 원본 UI 자산과 화면을 복제하지 않고 WorkBrain의 근거 비교·검토 흐름을 중심으로 독자 구성한다. [TickTick 기능](https://ticktick.com/features)

P1은 프로토타입 테스트에서 '30분 회의 초안 검토' 과제의 완료 시간·오류·되돌림 횟수를 기록한다. 작은 화면에서 근거 확인을 생략하도록 유도하면 승인 정확도 목표를 충족해도 UX를 보완한다.
